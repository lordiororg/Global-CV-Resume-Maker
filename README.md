# Files to upload to GitHub

Four files changed. Each keeps its original path, so you can drag them onto the matching
folder in the GitHub web uploader (or copy them over your local clone and commit).

| File here | Goes to | What it does |
|---|---|---|
| `index.html` | `index.html` | Adds the `src/ai.js` script tag and the **AI remap** panel (key field, Save / Remove, "re-map automatically after every upload") inside the **Extraction review** drawer. |
| `src/ai.js` | `src/ai.js` (**new file**) | The AI remap itself: sends the text read from the CV to Google's Gemini API, asks for a JSON object shaped like the CV record, and builds the record from the reply. |
| `src/app.js` | `src/app.js` | Wires it up: runs the AI remap automatically after an upload when a key is saved, adds the "AI remap" button, shows the AI status next to the import summary, and keeps the rule-based result if anything fails. Also contains the earlier PDF-export fix. |
| `src/styles.css` | `src/styles.css` | Styles for the AI panel (plus the earlier long-date wrap rule). |

Nothing else changed. `dist/` is generated by `npm run build`, so it does not need uploading —
the GitHub Actions workflow rebuilds it before deploying.

## About the AI key

No API key is in the code. Each person pastes their own free key from
<https://aistudio.google.com/apikey> into the app; it is stored in that browser's
`localStorage` and sent only to Google. The free tier covers this use comfortably:
the app picks a Flash-Lite model, which allows roughly 500 requests a day at no cost and
needs no card. Only one request is made per upload.

If the key is missing, rejected, or the daily quota is gone, the app says so and the
rule-based mapping stays exactly as it was.
